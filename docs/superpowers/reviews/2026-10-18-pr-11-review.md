## Findings and corrections

### R01 — P1: deployment ID prevents Vercel deployment

`next.config.ts` used the complete 64-character artifact hash as deploymentId.
Vercel rejects values longer than 32 characters. Its
[documented custom-ID contract](https://vercel.com/docs/skew-protection#custom-deployment-id)
also restricts characters/prefixes. The user's diagnostic identifies this exact
failure, and the configured value reproduces the length violation.

**Fixed:** retain the full artifact hash as BUILD_ID; generate a distinct
32-character hexadecimal deploymentId from it. Check the actual config and
bundled output. Hex satisfies the character/prefix restrictions and retains
128 bits of identity. Vercel and both Actions jobs passed on `99db446`; the
latest corrected head must pass again before completion.

### R02 — P1: independent rebuilds masquerade as the same artifact

The original identity was deterministic from source commit/tree and architecture.
Two independent Next builds could therefore advertise identical IDs despite
having different generated Server Action keys/manifests. This violates the
design's explicit random-artifact requirement and defeats version-skew detection
between such builds. Pinning replicas to one digest remains required separately.

**Fixed:** each actual npm build requests `--fresh`, generating a 128-bit random
build nonce folded into the full artifact hash. Typecheck/dev descriptor
generation can reuse an unchanged, internally valid descriptor. A fixture runs
the real generator: unchanged typechecking preserves identity; independent
fresh builds differ; changed source invalidates reuse; deployment IDs meet the
platform limit. Verification compares the image's commit/tree/architecture with
the checkout and validates its own bundled IDs, rather than equating independent
host-build and Docker-build IDs.

### R03 — P2: timed-out commands can falsely pass

The command helper sent SIGTERM on timeout/output overflow, then treated exit
code zero as success. A process that exits cleanly on SIGTERM makes an expired
check appear successful. The buffer also kept accepting output after overflow.

**Reproduced on Linux:** a Node child trapping SIGTERM and exiting zero returned
successful output after its 500 ms deadline (observed 519 ms). The same fixture
rejects with a timeout after the correction.

**Fixed:** retain the termination reason independently of exit code, bound the
retained byte buffer, stop collecting after failure, and escalate termination.
Regression cases cover ordinary success, nonzero exit, graceful termination on
deadline, output overflow and non-forwarding of a fixture DATABASE_URL.

### R04 — P2: mutable image tags weaken exact-image verification

Inspection resolved the image tag once, but subsequent run/Compose calls still
used that mutable tag. A concurrent retag could make later gates exercise an
image other than the one recorded in evidence.

**Fixed:** resolve the local immutable image ID once, use it in every subsequent
container/Compose call, and assert the running app/direct container's Image
matches it. Version/identity checks remain in addition to this binding.

### R05 — P2: summaries can omit a failing cleanup

Cleanup could fail after every registered check had recorded success. Although
the process then failed, its JSON summary contained only passing rows, making
the artifact misleading. Cleanup errors could also obscure a primary failure.

**Fixed:** cleanup is a recorded check; overall status stays running until every
gate and cleanup pass, and all failures set failed. Simultaneous verification
and cleanup failures preserve both errors. Network cleanup is registered before
the create attempt. A deliberately missing local image exits nonzero, records
overall failed and records successful cleanup of its temporary directory.
Successful end-to-end runs must record the additional cleanup gate.

### R06 — P3: early CI failures produce a second evidence-scan failure

The always-running scanner assumed the artifact directory existed even when a
previous install/build step failed before verification. Failed verification
summaries were also never uploaded, even after inspection.

**Fixed:** absence is reported without masking the original failure; existing
evidence is scanned before upload. Inspected summaries can be uploaded after
a failed check; rejected evidence is never uploaded. The job still fails on
its original failing step.

### R07 — P3: Compose download depends on an ephemeral feature branch

The download becomes a 404 after the normal deletion of the feature branch.

**Fixed:** pin the example to the initial P01 Compose commit. State that the
checkout supplies its matching revision and that downloading a file alone
does not provide a published application image.

### R08 — P3: custom database passwords need URL-encoding guidance

Compose interpolates POSTGRES_PASSWORD into a fallback URL. URL-reserved
characters cannot safely be inserted literally. The explicit DATABASE_URL
override supports these passwords, but that requirement was undocumented.

**Fixed:** document URL-unreserved passwords for the fallback and an explicitly
percent-encoded DATABASE_URL for other passwords. The URL and database service
password must refer to the same underlying value. No entrypoint or new runtime
configuration mechanism is introduced.
